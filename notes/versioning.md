# Правила версионирования (X.Y.Z)

Источник истины по версии — файл `VERSION` в корне репозитория.
Формат: `X.Y.Z` (SemVer-подобный).

## Кто и когда бампает

- **Z (patch)** — агент поднимает **автоматически** при каждом изменении кода,
  которое нужно протестировать / поправить. Счётчик без верхнего предела
  (…7 → 8 → 9 → 10 → …).
- **Y (minor)** — агент поднимает сам, если изменение **значимое**
  (новая фича, заметное изменение поведения). При бампе Y счётчик **Z сбрасывается в 0**.
- **X (major)** — **только по прямому указанию пользователя**.
  По умолчанию агент X не трогает никогда. При бампе X → Y и Z сбрасываются в 0.

## Автоматизация (release.ps1)

Скрипт `scripts\release.ps1` умеет бампать `VERSION` сам через флаг `-Bump`:



`VERSION` перезаписывается до чтения версии, поэтому и payload (`app.zip`),
и имя артефакта `release\BonjurLauncher_X.Y.Z.exe` получают уже новую версию.

## Процесс

1. Изменил код → выбрать уровень бампа (patch по умолчанию).
2. Запустить `release.ps1` с нужным `-Bump`.
3. Артефакт: `release\BonjurLauncher_X.Y.Z.exe`.
